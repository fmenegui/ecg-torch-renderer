# Swarm performance engineering assessment

## Scope and result

The optimized supervision postprocessor preserves bitwise output values while avoiding unnecessary per-lead allocations when callers request only combined masks (`trace_mask`, `bw`, `wb`). Requests for instance targets alone also skip lead-mask arithmetic. The renderer's raster math, random sequence, RGB output and per-lead supervision paths were not changed by this work.

This assessment measures target postprocessing on CPU. It does not establish an end-to-end rendering speedup. No CUDA device was available, so there is no GPU throughput, utilization, kernel occupancy or GPU-memory claim.

## Implementation

For nonnegative coverage masks `m[c]` and a shared nonnegative visibility mask `v`, `max_c(m[c] * v) == max_c(m[c]) * v`. Thresholding is also monotone, so the same reordering applies to binary unions. Consequently, requests without individual lead masks or lead boxes can reduce to one channel before visibility multiplication and binarization. Individual lead outputs retain the original operation order.

This assumes renderer target semantics: finite nonnegative coverage and visibility. The public `supervise` API expects a paired renderer result, rather than arbitrary signed arrays. Source tensors are never modified. Channel selection still occurs before union reduction, preserving requested subsets and order.

## Measured CPU microbenchmark

Environment: Python 3.12.14, PyTorch 2.14.1+cpu, x86_64 Linux, two torch CPU threads. Input mask shape `[2,12,384,512]`, float32 coverage and visibility generated with seed 93. Outputs requested: `trace_mask`, `bw`, `wb`, with `visible_only=True`. The already-rendered image and target inputs were excluded from allocation accounting.

| Union output | Upstream median ms | Optimized median ms | Upstream visible peak bytes | Optimized visible peak bytes | Bitwise output equality |
|---|---:|---:|---:|---:|---|
| Soft | 1.5593 | 0.5143 | 22,020,096 | 3,145,728 | Passed |
| Binary | 13.5852 | 0.8982 | 42,467,328 | 3,538,944 | Passed |

Timings are medians of ten block means, each block containing ten calls, after ten warmup calls per implementation. Baseline and optimized block order was randomized with a fixed seed. These measurements ran on a shared host, so clock variation and unrelated load can affect latency. Allocation counts provide the more portable evidence.

The baseline implements upstream `gpu_supervision.py` from revision `0d8cc055`. The upstream SHA-256 is `5f127cd49659962547a0030482bf36d27c545c4cc40e5a718f7059974b9e535a`. The measured staging copy had one additional trailing newline, giving SHA-256 `00357ab1b14c7a13032077512930e99489b0a86512132e3c8b989f0ad10e2625`, with identical executable code. The initial local Git snapshot was created while agents were editing files, so it is deliberately not used as the baseline.

`TensorLedger` tracks live public ATen result storage with alias deduplication. Its visible peak excludes allocator fragmentation, backend workspaces, pre-existing inputs and renderer buffers. Created bytes are allocation volume, not measured DRAM traffic. These CPU values are not CUDA memory measurements. Image generation and image encoding are absent from this microbenchmark.

## Verification

Executed `python -m unittest tests.test_performance_contracts tests.test_supervision -v`: 14 tests, 13 passed and one skipped because CUDA hardware was unavailable.

The new contracts check exact equality between combined-only and full-lead supervision across soft/binary outputs, visible/projected masks, and full/subset lead selection. They check input immutability and require that union-only processing not allocate another full twelve-lead float tensor. They do not impose machine-dependent latency thresholds. Existing tests cover paired RGB/masks, boxes, visibility, repeated instances, training gradients, replay state, export and absence of host transfers or scalar reads.

## Hot-path audit and follow-up

- `curve_coverage` uses full image-height intermediates for every antialias sample and curve chunk. Exact tiling could reduce peak memory, but changes require equivalence checks at crossings, clipping boundaries and signal extrema. Raster changes were left to the fidelity reviewer and deferred to retain frozen-render compatibility.
- The renderer's instance-box extraction previously formed `(visible > .05)` separately for row and column occupancy. Sharing that boolean tensor avoids one large temporary without changing threshold semantics. This finding was sent to the renderer owner.
- Dense traces are still generated by `stage='trace'` even for combined-only supervision. The present optimization removes extra postprocessing allocations. It does not eliminate the renderer's original twelve-channel trace target.
- Image effects such as camera JPEG simulation operate on full batches even when some per-record strengths or activation flags are zero. A tensor-valued Python branch would cause device synchronization. Any future skip path must be selected from static configuration and preserve the random stream, or use measured compiled kernels.
- Compilation is opt-in. No compiled speedup was measured in this assessment. Cold compilation time, warm latency and shape specialization should be reported separately.

## GPU acceptance procedure

Before making GPU speed or production throughput claims, run the existing profiler on the intended GPU, first with the intended renderer configuration and then with the actual model training workload:

```bash
python -m ecg_gpu.profile --device cuda --preset balanced --batch-size 4 --steps 20 --warmup 5 --profile-steps 3 --out /tmp/ecg-gpu-profile
python -m ecg_gpu.profile --device cuda --preset balanced --batch-size 4 --steps 20 --warmup 5 --profile-steps 3 --train-step --out /tmp/ecg-gpu-train-profile
```

Use separate empty output directories. Compare eager and compiled configurations under identical resolution, batch size, antialiasing, targets and scene settings. Inspect device event latency, synchronized host latency, peak allocated/reserved memory and actual captured kernel activities. Validate soft/binary target parity on CUDA with selected lead subsets. Increase batch size only after measuring available memory with the real training network and optimizer. These commands were not executed on CUDA here.

## Reproduction script

Save the following as a temporary script and pass a locally checked copy of the upstream supervision source as its first argument. Verify the SHA-256 above before running. Execute from the repository with `PYTHONPATH=.`. It benchmarks the real old and new `supervise` implementations without modifying repository files.

```python
import gc
import json
import platform
import random
import statistics
import subprocess
import sys
import time
import types
from types import SimpleNamespace

import torch
from ecg_gpu.gpu_supervision import ECGSupervisionLayer, SupervisionConfig
from ecg_gpu.audit import TensorLedger
from ecg_gpu.schema_v05 import LEADS

source = open(sys.argv[1]).read()
baseline_module = types.ModuleType('ecg_gpu._baseline_supervision')
sys.modules[baseline_module.__name__] = baseline_module
exec(compile(source, '<baseline-supervision>', 'exec'), baseline_module.__dict__)
torch.set_num_threads(2)
generator = torch.Generator().manual_seed(93)
rendered = SimpleNamespace(image=torch.rand(2, 3, 384, 512, generator=generator),
    targets={'traces': torch.rand(2, 12, 384, 512, generator=generator),
             'valid': torch.rand(2, 1, 384, 512, generator=generator)})

def make(cls, binary):
    layer = cls.__new__(cls)
    torch.nn.Module.__init__(layer)
    layer.supervision = SupervisionConfig(outputs=('trace_mask', 'bw', 'wb'), binary=binary)
    layer.register_buffer('_lead_indices', torch.arange(12), persistent=False)
    return layer

report = {'environment': {'python': platform.python_version(), 'torch': torch.__version__,
          'threads': torch.get_num_threads(), 'cuda_available': torch.cuda.is_available(),
          'platform': platform.platform(), 'machine': platform.machine()},
          'shape': [2, 12, 384, 512], 'method': 'Alternating randomized order of 10 blocks per version, 10 calls per block, after 10 warmup calls. No renderer, I/O, signal transfer or compilation.',
          'upstream_revision': '0d8cc055',
          'cases': []}
for binary in (False, True):
    layers = {'baseline': make(baseline_module.ECGSupervisionLayer, binary),
              'optimized': make(ECGSupervisionLayer, binary)}
    expected = layers['baseline'].supervise(rendered)
    observed = layers['optimized'].supervise(rendered)
    assert all(torch.equal(expected[key], observed[key]) for key in expected)
    del expected, observed
    for layer in layers.values():
        for _ in range(10):
            layer.supervise(rendered)
    times = {name: [] for name in layers}
    rng = random.Random(5)
    for _ in range(10):
        order = list(layers)
        rng.shuffle(order)
        for name in order:
            start = time.perf_counter()
            for _ in range(10):
                result = layers[name].supervise(rendered)
                del result
            times[name].append((time.perf_counter() - start) * 100)
    case = {'binary': binary, 'bitwise_equal': True, 'versions': {}}
    constants = [rendered.image, *rendered.targets.values()]
    for name, layer in layers.items():
        with TensorLedger(constants + list(layer.buffers())) as ledger:
            result = layer.supervise(rendered)
        del result
        gc.collect()
        case['versions'][name] = {'median_ms': statistics.median(times[name]),
                                 'block_mean_ms': times[name],
                                 'ledger': ledger.report()}
    report['cases'].append(case)
print(json.dumps(report, indent=2))

```
